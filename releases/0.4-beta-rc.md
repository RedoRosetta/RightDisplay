## 简体中文

0.4 将显示状态、日常控制和诊断整理到更清楚的六页界面，新增独立 ICC 色彩描述文件页面，并加入仍在解决公开分发问题的 Virtual Audio 软件音量。

> **Virtual Audio 已知问题：** 当前组件签名检查与 ad-hoc 分发方式存在兼容问题，可能导致软件音量转发无法启动；本公开包的跨机器安装和实际播放仍未验证完成。组件要求 **macOS 27+**。如果你主要需要 HDMI / DP 软件音量，建议等待修复。使用显示、ICC、EDID、Quick Control 或 Apple TV 功能不要求安装虚拟音频组件。

### 本次变化

- **更清楚的界面：** 概览、显示、音频、ICC、EDID、通用六页重新整理；Quick Control 将常用控制放在菜单栏，并与完整窗口共享状态。
- **ICC 色彩描述文件：** 查看当前描述文件、检查外部 ICC、确认后应用可用描述文件；查看白点、原色、色调曲线、色域和 VCGT 数据。
- **显示输出：** 区分固定刷新率与 VRR，保留系统提供的不同时序；按颜色格式、色深、范围与 HDR 的完整组合处理，并在调整后重新读取系统状态。
- **可选 Virtual Audio：** 为 HDMI / DP 设计的软件音量路径，包括目标保存、条件满足时自动启动、手动停止保留和异常后的显式恢复。当前受上方已知问题限制。
- **保留常用功能：** 配置保护、切换确认与恢复尝试、主动链路测试、本地诊断，以及兼容 Apple TV 的输出音量与支持的键盘控制。HomePod 沿用 Apple TV 当前／默认输出路径。

### 安装与从 0.3 升级

1. 下载 `RightDisplay-0.4-Beta-RC-arm64.zip`；**Source code 不是应用安装包**。
2. 正常退出旧版并保留副本，解压后把 `Right Display.app` 拖入「应用程序」，替换整个 App。
3. 当前 App 为 ad-hoc 签名，未使用 Developer ID 签名、未经过 Apple 公证。若 macOS 无法验证开发者或检查 App，确认官方来源后按「系统设置 → 隐私与安全性 → 仍要打开」操作。无需关闭 Gatekeeper 或 SIP。
4. 打开后点击菜单栏图标，先查看「概览」。虚拟音频是可选项；**只替换 App 不会更新已安装的音频组件**。

[完整安装、首次启动、音频组件与卸载步骤](https://github.com/RedoRosetta/RightDisplay/blob/main/INSTALLATION.md)

### 使用边界

- 可用显示模式取决于 Mac、macOS、显示器、线材及转接设备。切换或链路测试可能短暂黑屏；恢复为尝试，不保证成功。
- 系统报告不等于显示器接收端的物理测量；EDID 表示声明能力，DSC 保持推断。ICC 图表描述文件数据，不是屏幕实测或当前 GPU 校准状态。
- Virtual Audio 调节软件增益，不调节电视硬件音量；100% 对应内部 0 dB，不构成物理 bit-perfect 输出承诺。就绪或绿灯不能替代实际播放确认。
- 虚拟音频组件还有同一登录用户的其他本地进程可能冒充音频客户端或占用连接的限制，详见[安全说明](https://github.com/RedoRosetta/RightDisplay/blob/main/SECURITY.md)。

## English

0.4 organizes display status, everyday controls and diagnostics into six clearer pages, adds a dedicated ICC color-profile page, and introduces Virtual Audio software volume with an unresolved public-distribution issue.

> **Known Virtual Audio issue:** Component signature checks conflict with this ad-hoc distribution and may prevent software-volume forwarding from starting. Cross-machine installation and actual playback of this public package have not yet been fully verified. The component requires **macOS 27+**. If HDMI / DP software volume is your main need, we recommend waiting for a fix. Display, ICC, EDID, Quick Control and Apple TV features do not require installing virtual-audio components.

### What changed

- **Clearer interface:** Overview, Display, Audio, ICC, EDID and General are reorganized. Quick Control brings common controls to the menu bar and shares state with the full window.
- **ICC color profiles:** Inspect the current profile or an external ICC file, apply available profiles after confirmation, and view white point, primaries, tone curves, gamut and VCGT data.
- **Display output:** Fixed refresh rates and VRR remain distinct, preserving available system timings. Color format, depth, range and HDR are handled as a complete combination, with a fresh system read after changes.
- **Optional Virtual Audio:** A software-volume path designed for HDMI / DP, with saved targets, conditional auto-start, retained manual stops and explicit recovery after abnormal stops. It is currently limited by the issue above.
- **Everyday features continue:** Configuration Protection, confirmation and attempted recovery, optional link testing, local diagnostics, compatible Apple TV output volume and supported keyboard controls. HomePod follows Apple TV’s current/default output path.

### Install or upgrade from 0.3

1. Download `RightDisplay-0.4-Beta-RC-arm64.zip`. **Source code archives are not installable apps.**
2. Quit the old version normally and retain a copy. Extract the ZIP and drag `Right Display.app` to Applications, replacing the whole App.
3. The App is ad-hoc signed, without Developer ID signing or Apple notarization. If macOS cannot verify the developer or check the App, confirm the official source, then use **System Settings → Privacy & Security → Open Anyway** where offered. Do not disable Gatekeeper or SIP.
4. Open it, click the menu-bar icon and start with Overview. Virtual Audio is optional; **replacing the App does not update installed audio components**.

[Full installation, first launch, audio-component and removal guide](https://github.com/RedoRosetta/RightDisplay/blob/main/INSTALLATION.md#english)

### Limitations

- Available display modes depend on the Mac, macOS, display, cable and adapters. Switching or link testing may blank the screen; recovery is attempted, not guaranteed.
- System reports are not physical measurements at the display receiver. EDID advertises capabilities; DSC stays inferred. ICC plots describe file data, not measured display output or current GPU calibration.
- Virtual Audio changes software gain, not TV hardware volume. 100% means 0 dB internally, not a physical bit-perfect guarantee. Ready/green status does not replace an actual playback check.
- Virtual-audio components also have a limitation where another local process under the same logged-in user may impersonate an audio client or occupy a connection. See [security information](https://github.com/RedoRosetta/RightDisplay/blob/main/SECURITY.md).

### Share feedback

Tell us whether first installation works, everyday display controls behave as expected, or you encounter wake, reconnection or ICC problems. Intermittent issues are welcome. Virtual Audio failing to start is known; new installation errors, crashes or different behavior are still useful to report.

[Report an issue](https://github.com/RedoRosetta/RightDisplay/issues/new/choose) with **0.4 Beta RC**, your Mac and macOS version, what happened and the expected result. Diagnostics are saved locally on request; review them for private information before uploading.

This RC remains a public prerelease. The path to 0.4 Beta Final is real-world feedback, clear blockers, the Virtual Audio distribution issue and necessary documentation fixes. Incomplete runtime verification is not treated as completed.
