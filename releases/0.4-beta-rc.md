# RightDisplay 0.4 Beta RC

**Apple silicon · arm64 · Public RC**

[下载 RightDisplay 0.4 Beta RC](https://github.com/RedoRosetta/RightDisplay/releases/tag/v0.4-beta-rc)

RightDisplay 0.4 重新整理了显示状态、控制和诊断的组织方式，并加入两个新的主要功能：**ICC Color Profiles** 和 **Virtual Audio 软件音量**。

完整窗口现在分为概览、显示、音频、ICC、EDID、通用六个页面，Quick Control 也同步更新。

> **已知问题**
>
> 当前 RC 使用 ad-hoc 签名。Virtual Audio 仍有部分组件签名检查与这种分发方式不兼容，因此软件音量可能无法启用。
>
> 这一问题不影响显示控制、ICC、EDID、Quick Control、Apple TV 等其他功能。Virtual Audio 当前要求 macOS 27.0 或更新版本。

## 重新整理的显示界面

0.4 对 RightDisplay 的完整窗口进行了重新设计。

概览现在集中展示：

- 分辨率与 HiDPI
- 刷新率与 VRR
- 当前连接
- RGB / YCbCr
- 色深
- HDR
- DSC

显示页则集中负责实际控制，包括分辨率、HiDPI、固定刷新率、VRR、颜色输出、色深、HDR 和亮度。

相比 0.3，这一版减少了重复信息，也重新整理了卡片、控件和状态提示，让“当前是什么状态”和“可以调整什么”更容易区分。

## 刷新率、VRR 与颜色输出

固定刷新率和 VRR 现在分开呈现。

RightDisplay 保留 macOS 实际提供的不同时序，例如：

`120 Hz` · `119.88 Hz` · `60 Hz` · `59.94 Hz`

不会自行合并或生成系统没有提供的刷新率。

颜色输出继续按照完整组合处理：

**颜色格式 × 色深 × 范围 × HDR**

例如 `RGB · 12-bit · Full · HDR` 与 `YCbCr 4:4:4 · 10-bit · Limited · HDR` 会作为不同的输出状态处理。

设置之后，RightDisplay 会重新读取系统状态，而不是仅根据设置请求的返回结果判断是否已经切换成功。

## 新增：Virtual Audio 软件音量

部分 HDMI / DisplayPort 音频设备在 macOS 中没有可用的系统音量控制。

0.4 加入 Virtual Audio，将系统声音通过 RightDisplay 的虚拟输出转发到指定的真实 HDMI / DP 设备，并在转发过程中提供软件音量。

主要包括：

- HDMI / DP 软件音量
- 静音
- 键盘音量控制
- 保存真实输出目标
- 条件满足时自动启动
- 手动停止状态保留
- 异常停止提示
- 显式重新启动
- 转发状态与运行原因

这是**软件音量**，不会改变电视或显示器自身的硬件音量。

当目标输出消失或转发条件不再满足时，RightDisplay 不会自动把声音切换到 Mac 扬声器。

### 当前 RC 的 Virtual Audio 限制

本次公开 RC 使用 ad-hoc 签名，而当前版本仍保留部分 RightDisplay App、broker 和 driver 之间的 Apple 签名检查。

这些检查与当前 ad-hoc 分发方式并不完全兼容，因此 **Virtual Audio 可能无法启动转发**。

Virtual Audio 的实际公开分发仍在继续完善；其他 0.4 功能不受这一问题影响。

## 新增：ICC Color Profiles

ICC 在 0.4 中成为独立页面。

可以查看当前显示器关联的 Color Profile，也可以打开其他 ICC 文件进行检查，包括：

- Profile 类型与版本
- Color Space / PCS
- 白点
- RGB 原色
- RGB Matrix
- Tone Response Curve
- VCGT
- CIE 1931 xy 色域关系

可用的描述文件可以在确认后应用，并通过 macOS 的关联状态进行回读。

新增的色域和 VCGT 图表描述的是 **ICC 文件中的模型与数据**，不是色度计实测结果，也不代表 GPU 当前一定加载了文件中的校准 LUT。

## EDID 与显示器能力

EDID 页面重新整理了显示设备声明的能力和 macOS 已解析的信息，包括：

- 厂商与型号
- 原生分辨率
- HDR / PQ / HLG
- BT.2020
- 刷新率
- VRR 范围
- 色度信息
- 原始 EDID

0.4 继续区分 **设备声明的能力** 与 **当前输出状态**。

EDID 声明支持 HDR、12-bit 或 VRR，并不意味着当前连接正在使用这些能力。

## Quick Control 更新

Quick Control 与完整窗口重新统一了状态和控制逻辑。

快捷面板可以访问：

**亮度 · 音量 · 颜色格式 · 色深 · HDR · VRR**

显示哪些快捷项目可以在通用设置中管理。

## 配置保护与恢复

配置保护可以锁定显示相关的手动调整，减少已经调好的显示设置被意外改变，同时保留亮度和音量等日常控制。

需要确认的显示模式切换提供倒计时；如果没有确认，RightDisplay 会尝试恢复切换前的设置。

显示链路测试继续使用当前连接实际提供的模式检查颜色格式、色深和 HDR / SDR 组合。测试需要主动开始，过程中可能出现短暂黑屏或重新握手。

## Apple TV 与 HomePod

Apple TV 音量控制继续保留，并重新整理了连接状态和界面。

兼容设备可以使用输出音量、静音和键盘音量控制。

当 HomePod 作为 Apple TV 当前或默认音频输出时，可以跟随 Apple TV 的音频控制路径。

Apple TV 控制与 Virtual Audio 是两套独立功能：前者控制设备提供的可写音量，后者为 HDMI / DP 提供软件音量。

## 诊断与通用设置

诊断报告继续整合当前显示状态、模式、EDID、链路证据、音频状态以及近期操作。

报告只会在用户主动操作时保存到本地，不会自动上传。

通用设置现在集中管理：

- 跟随系统 / 简体中文 / English
- 登录启动
- Quick Control 项目
- 安全模式
- 自动校正

安全模式主要用于抑制启动、连接变化和唤醒时的自动校正；需要阻止手动显示调整时，可以使用配置保护。

## 关于显示状态与证据

RightDisplay 会尽量区分：

**macOS 当前报告的状态 · 显示器声明的能力 · 根据现有信息得到的推断**

SLS 报告的当前状态可以用于控制和回读，但不等于显示器接收端的物理测量结果。

DSC 等无法直接确认的状态仍会标记为推断；EDID 表示设备声明的能力；ICC 图表表示描述文件中的数据。

RightDisplay 的目标不是把这些来源混在一起给出一个看起来更确定的答案，而是在现有证据范围内尽量准确地告诉你当前知道什么。

## 下载与安装

下载：

- `RightDisplay-0.4-Beta-RC-arm64.zip`
- `SHA256SUMS.txt`

当前 RC：

- Apple silicon / arm64
- 基础功能需要 macOS 14 或更新版本
- Virtual Audio 当前需要 macOS 27.0 或更新版本
- ad-hoc signed
- 尚未经过 Apple 公证

解压后，将 `Right Display.app` 放入「应用程序」。

如果 macOS 阻止首次打开，请使用系统提供的正常方式：

**系统设置 → 隐私与安全性 → 仍要打开**

或在 Finder 提供该选项时选择 **打开**。

**不需要关闭 Gatekeeper，也不需要关闭 SIP。**

Virtual Audio 需要单独安装对应的音频组件。完整步骤见 [安装说明](../INSTALLATION.md)。

## 从 0.3 升级

退出旧版本后，可以直接替换 `Right Display.app`。

0.4 对界面和功能组织进行了较大调整，升级后建议重新查看「通用」和「音频」页面。

如果需要使用 Virtual Audio，请按照新的安装说明处理对应组件；仅替换 App 不会更新已经安装的 broker / driver。

## 反馈

0.4 Beta RC 是公开测试候选，不是最终的 0.4 Beta。

如果遇到显示状态识别错误、模式切换异常、HDR / VRR / RGB / YCbCr 与预期不符、ICC 描述文件问题，或者其他可以稳定复现的问题，欢迎通过 [Issues](https://github.com/RedoRosetta/RightDisplay/issues) 提交。

Virtual Audio 在当前 ad-hoc RC 中无法启用属于已知问题；如果遇到不同的安装异常、崩溃或其他表现，也欢迎反馈。
